# Unity-only アリーナゲーム企画・仕様書

作成日: 2026-09-05

状態: Unity-only初版の実装仕様。ユーザー指定と、実装時に採用した初期案を分けて記載する。検証結果は[検証表](unity-only-arena-verification.md)に記録する。

作業範囲: 仕様定義に続く実装依頼に基づき、オープニングメニュー・設定画面・3種類のアイテムを含むUnity-onlyデモを実装・検証する。開発で観測した困りごとは[ペインログ](../unity-only-arena-pain-log.md)に残す。

## 1. 目的と扱い

小さなトップダウンアクションアリーナを、まずUnityだけで実装する。
オープニングメニュー、設定、準備、戦闘、フロア攻略、報酬の選択、強化、次の攻略、死亡、リザルト、再挑戦がつながり、ゲームのシステムとして成立することを目標とする。

初版では面白さ、爽快感、演出品質、アセット品質を完成条件にしない。キャラクターや地形は単純な図形でよい。
演出、アセット、プレイフィールはユーザーが後から改善する。
ただし、向き、攻撃範囲、ダメージ、装備効果、進行状態を確認できる最低限の表示は必要とする。

本書では以下の区分を使う。

- **指定**: ユーザーが提示・回答した仕様。数量に「目安」があるものはそのまま調整可能とする。
- **提案**: 実装中の判断漏れを減らすための初期案。ユーザーによる確定事項ではない。
- **調整値**: ルールを変えずに後から変更できる数値やコンテンツ構成。

第2章以外の追加ルールは、明記した指定事項を除き提案である。実装依頼を受けて以下の初期案を初版に採用した。ユーザーが個別に指定した事項とは区別し、今後変更できる設計判断として扱う。

## 2. ユーザー指定の基本仕様

### 進行

- オープニングメニューと設定画面を用意する。
- 典型的なトップダウン視点のアクションアリーナ。
- レベルは小さなフロア。広大なオープンワールドにはしない。
- 開始直後は敵がいない準備フロア。次のフロアへのワープポータルがある。
- 戦闘フロアでは敵が出現し、すべて倒せばクリア。
- クリアするとワープポータルが出現し、入ると次のフロアへ進む。
- 先のフロアほど徐々に難易度が上がる。
- 5フロアごとを目安にボスが出現する。
- **HPが0になるまで続くエンドレス方式。最終フロアや勝利によるラン終了は設けない。**
- プレイヤーのHPが0になるとゲームオーバー。プレイリザルトを表示する。

### 報酬・所持品

- 開始直後のフロアとボス撃破後に、装備品やアップグレードアイテムを含む箱が出現する。
- プレイヤーはバックパックと装備スロットを持つ。
- バックパック容量は3を目安とする。
- 装備スロットはアイテムA、アイテムB、武器A、武器B。
- アイテムA/Bには、まず次の3種類を用意する。
  - 救急キット: 使用するとHPを全回復し、そのアイテムを失う。
  - 手榴弾: 投げると爆発して大きなダメージを与え、そのアイテムを失う。
  - シールド: 装備中はHPの代わりにダメージを受ける。HPと同じ容量を持ち、時間とともに回復する。
- 箱にはインベントリ容量より多くのアイテムを入れ、取捨選択が必要な構成にする。
- 敵はアイテムをドロップしない。

### 操作・コンバット

- WASDで移動する。
- マウスでエイムとプレイヤーの向きを制御する。
- 左クリックで武器A、右クリックで武器Bを使用する。
- ZでアイテムA、XでアイテムBを使用する。シールドの自動防御とキー入力の扱いは第9章で補足する。
- 敵のHPが0になると撃破。
- 初版の敵は雑魚3種類、ボス1種類。
- キャラクター等は単純な図形のプレースホルダでよい。

## 3. 実装前に決めたい追加事項と初期案

下表は、単なる数値調整よりも状態管理や操作の設計に影響する論点である。

| 論点 | 初期案 | 決める理由 |
| --- | --- | --- |
| ランの終点 | **指定: 死亡までエンドレス** | 最終ボス、勝利画面、報酬後の遷移の有無が変わる |
| フロアの数え方 | 準備を0F、戦闘を1Fから数え、5の倍数をボスにする | 難易度計算、報酬タイミング、リザルトをそろえる |
| ボスフロアの構成 | 雑魚を置かず、同じボス1体を強化して再利用 | クリア条件と必要コンテンツを限定できる |
| アイテムA/Bの意味 | **指定: 救急キット・手榴弾・シールド。AはZ、BはX** | 消費型と自動防御型の処理、使用後の空き枠を定義する |
| シールドの詳細 | 容量はプレイヤーの最大HP。装備中に自動防御・回復。枯渇しても失わない | 「HPと同じ容量」の基準、ダメージ超過分、回復・付け外しを決める |
| アップグレードの意味 | 消費するとラン中ずっと効く能力強化 | 装備個体の改造か、プレイヤー強化かで保持する状態が変わる |
| 成長の経路 | 装備と箱のアップグレードのみ。XP・レベル制は初版に追加しない | 成長ルールの重複を避け、今回の箱中心の進行を定義する |
| HP回復 | 救急キットで全回復（指定）。開始時・ボスフロアクリア時も全快とし、通常フロアでは自動回復なし | 消耗品の使用と進行による回復を区別する |
| 所持品の変更タイミング | 準備・クリア後のみ。所持品UIを開くとゲーム進行を停止 | 戦闘中の装備変更、効果の付け外し、入力競合の扱いが変わる |
| 攻撃の基本 | 押しっぱなしで繰り返し、A/Bは独立クールダウンで同時使用可 | 武器状態、入力処理、武器間の競合を決める |
| 箱と容量 | 装備枠はバックパックと別。箱には保持しきれない数の装備候補を用意 | バックパック3枠より多いだけでは選択が発生しない |
| マップ・乱数 | 初版は同じ固定アリーナ、固定出現地点、規則的な敵構成、固定の箱内容 | ランダム生成や再現用シードの仕様を初版の必須条件から外せる |
| 再挑戦・保存 | リザルトから新規ラン。持ち越し・途中セーブなし | 初期化範囲とラン外のデータを確定する |
| メニュー・設定 | オープニングは開始・設定・終了。設定は全体音量と画面モードを保存 | 起動、ポーズ、設定からの戻り先、ラン状態と設定の保存範囲を決める |

シールドの回復・複数装備、アップグレード対象、ボス後の回復、戦闘中の所持品操作、設定項目は、本書の初期案を使う。
武器ダメージ、移動速度、敵数、箱の個別候補などの調整値は、動作確認用の仮値として実装する。

## 4. ランとフロアの進行

1. 起動時にオープニングメニューを表示する。「ゲーム開始」で新規ランを開始し、0Fの準備フロアにプレイヤー、箱1個、ポータル1個を出す。
2. 箱で所持品を選び、装備・強化する。箱を利用せず進むこともできる。
3. ポータルに入ると1Fへ移動し、そのフロアの敵を一度だけ出現させる。
4. 通常フロアは敵を全滅させるとクリアし、ポータル1個が出る。
5. 5F、10F、15F……はボスフロア。ボス撃破後に箱1個とポータル1個が出て、HPが全回復する。
6. 報酬の整理後、ポータルから次のフロアへ進む。この周期を繰り返す。
7. どの戦闘フロアでもプレイヤーのHPが0になれば、その時点でランを終了する。

### 状態と遷移条件

| 状態 | できること・遷移条件 |
| --- | --- |
| オープニングメニュー | ゲーム開始、設定、アプリ終了。ランはまだ動いていない |
| 設定 | オープニングまたはポーズから表示。適用・キャンセル後は開いた元の画面へ戻る。ランは進行しない |
| 準備 | 移動、試し撃ち、箱・所持品の操作。ポータルから1Fへ |
| フロア移動中 | ゲーム入力を停止。前フロアを片付け、新フロアを配置 |
| 戦闘中 | 移動・攻撃・装備アイテム使用・ポーズ。敵の残数が0ならクリア、HPが0ならゲームオーバー |
| フロアクリア | 敵の攻撃や残存弾による被害がない安全状態。所持品整理と次フロアへの移動が可能 |
| ポーズ | 元のラン状態を保持して停止。再開、設定、オープニングへ戻る操作が可能 |
| リザルト | 戦闘・移動・所持品変更を停止。再挑戦で新規ランを初期化、またはオープニングへ戻る |

- 敵は入場時に一括で出す。追加ウェーブ、時間湧き、増援は初版に含めない。
- クリア判定は予定した全敵の配置が完了してから有効にする。配置前の敵数0でクリアしない。
- ボスの全回復、箱、ポータルはクリア時に一度だけ発生する。箱の再表示では回復しない。
- フロアクリア時とフロア移動時に、残っている弾・手榴弾・爆発・攻撃判定を消す。投げて消費した手榴弾は戻さない。
- ポータルはクリア後の固定位置に出す。出現した瞬間にプレイヤーが重なっていても移動させず、一度範囲外へ出てから入り直したときに反応する。
- ポータル反応から移動完了までは再反応を禁止し、重複移動を防ぐ。
- 次のフロアへ進むと前のフロアへは戻れない。取り残した箱の中身も回収できない。
- 戦闘フロアへ進むには武器を少なくとも1つ装備している必要がある。未装備なら案内を表示して移動しない。
- 箱・所持品UI表示中はポータルが反応しない。

## 5. フロア・視点・移動

- シングルプレイヤー、PCのキーボードとマウスを初版の対象とする。
- 平面上を移動する3D表現とし、高さ方向の移動、ジャンプ、段差は使わない。
- カメラは斜め上から見下ろす固定向きの正投影。床面に対する俯角55度を初期値とし、アリーナ中央を見る。左右方向には回転させず、WASDと画面上の上下左右の対応を保つ。小さなアリーナ全体と外周が画面に収まる構成にする。
- 全フロアで同じ四角い部屋を使い、まずは外周壁だけを置く。迷路、扉、内部障害物、地形生成は不要。
- WASDは画面上の上下左右に対応する。斜め移動で速度が増えないようにする。
- マウス位置を床面上の位置として解釈し、その方向を向く。方向が定まらない場合は最後の有効な向きを維持する。
- プレイヤーと敵は壁を通過しない。キャラクター同士は移動を塞がず、押し合いも起こさない。
- 敵との接触そのものではダメージを受けない。ダメージは攻撃判定だけで発生する。
- 入場位置、敵出現地点、箱、ポータルの位置を固定し、入場位置は敵の初期攻撃範囲の外に置く。

アリーナの一辺20、プレイヤー速度5/秒を仮の調整値とする。地形や見た目の差し替えで攻略・報酬ルールを変える必要がない構成にする。

## 6. 操作

| 入力 | 動作 |
| --- | --- |
| WASD | 移動（指定） |
| マウス移動 | エイム・向きの変更（指定） |
| 左クリック / 右クリック | 武器A / 武器Bを使用（指定）。長押しで使用間隔ごとに繰り返す |
| Z / X | アイテムA / アイテムBを使用（指定）。消費型は1回押すごとに1個使用。シールドは自動防御のためキーで発動しない |
| E | 近くの箱を開く。操作可能距離は仮に2とする |
| Tab | 安全状態で所持品UIを開閉。戦闘中は開かず、その旨を表示 |
| Esc | 設定ではキャンセルして元のメニューへ戻る。箱・所持品UIでは閉じる。ラン中はポーズ、ポーズ中は再開 |
| R / 再挑戦ボタン | リザルトで新規ランを開始 |

- 箱・所持品UIは一覧とボタンで操作する。ドラッグ操作は初版の必須条件にしない。
- メニュー・設定・箱・所持品など操作用UIの表示中は、移動、攻撃、アイテム使用、AI、弾・手榴弾、クールダウン、シールド回復とその待ち時間、ラン時間を停止する。常時HUDは停止対象ではない。
- UI操作のクリックで武器を使用しない。UIを閉じた後の攻撃・アイテム使用は、それぞれのボタン・キーを離してから改めて押した場合に受け付ける。
- 装備のない武器・アイテムスロットの入力は何も発生させない。
- アプリが非アクティブになった場合はポーズする。復帰後は明示的に再開する。

## 7. コンバット

### プレイヤーと武器

- プレイヤーの基礎最大HPは100。初期状態では武器Aに基本近接武器、他の装備枠とバックパックは空。
- 攻撃中も移動とエイムを継続できる。武器A/Bは独立したクールダウンを持ち、同時使用できる。
- 武器の弾薬・リロード・耐久度、スタミナ、マナ、クリティカル、属性相性は初版に含めない。消費アイテムの個数とシールド容量は別途管理する。
- プレイヤーは敵だけを、敵はプレイヤーだけを攻撃する。味方同士のダメージはない。
- ダメージは攻撃力と強化倍率から算出する整数値。正のダメージは小数点以下切り捨て、最低1とする。
- 被弾による無敵時間、ノックバック、ひるみは初版に含めない。別の攻撃が同時に当たればそれぞれダメージを与える。

### 最小の武器3種類（提案・数値は調整値）

| 武器 | 攻撃ルール | 仮の基本値 |
| --- | --- | --- |
| ブレード | 発動時の向きに扇形の近接判定。範囲内の各敵に1回ずつ命中 | ダメージ20、間隔0.5秒、射程2、角度90度 |
| シューター | 発射時の向きへ直進弾1発 | ダメージ12、間隔0.25秒、弾速12、最大飛距離12 |
| ヘビーシューター | 発射時の向きへ遅い直進弾1発。爆風なし | ダメージ50、間隔1秒、弾速7、最大飛距離10 |

- 同じ武器種をA/Bのどちらにも装備できる。同種を両方に装備する場合は別の所持個体が必要。
- 近接は1回の発動につき同じ敵に重複命中しない。
- 弾は最初の対象への命中、壁への衝突、最大飛距離で消える。貫通・誘導・跳弾はない。
- 弾のダメージは発射時の能力値で確定する。
- 攻撃範囲や命中の発生はアニメーション素材の有無に依存させない。

### ダメージと終了処理

- HPは0未満にしない。死亡した敵はそれ以降移動・攻撃・被弾しない。
- プレイヤーへのダメージは第9章のシールドで吸収してから、残った分だけHPを減らす。救急キット・シールドで死亡確定後に復活することはない。
- 敵1体の死亡、撃破数加算は1回だけ処理する。
- 同じ更新で確定したダメージを反映してから死亡とフロアクリアを判定する。
- 最後の敵とプレイヤーのHPが同じ更新で0になった場合はゲームオーバーを優先する。その敵の撃破は記録するが、フロアクリア・ボス報酬・全回復は発生しない。

## 8. 敵と難易度

### 敵の最小構成

| 種類 | 行動 | 仮の基礎値 |
| --- | --- | --- |
| 追跡型 | プレイヤーへ直進し、近接射程に入ると停止して一定間隔で攻撃 | HP40、速度2.5、ダメージ10、射程1.5、間隔1秒 |
| 射撃型 | 距離6より遠ければ接近。距離6以内では停止し、その時点のプレイヤー方向へ直進弾 | HP30、速度2、ダメージ8、間隔1.5秒、弾速6、飛距離12 |
| 重装型 | 追跡型と同じルールで、遅く、HPと攻撃力が高い | HP100、速度1.2、ダメージ20、射程1.8、間隔1.5秒 |
| ボス | 追跡・近接攻撃に加え、周期的に停止して放射状の弾を撃つ | HP300、速度1.5、近接20、射程2、間隔1.5秒、弾12 |

- 敵はプレイヤーの位置を認識している。索敵、視線遮蔽、経路探索、撤退、召喚は不要。
- 敵の近接攻撃は発動時に距離内なら1回命中する。出現直後は通常の攻撃間隔を待ってから初回攻撃する。
- ボスは3秒間追跡・近接攻撃、0.8秒停止予告、全周へ8方向の弾を同時発射、1秒停止後に追跡へ戻る。予告・発射・停止中は近接攻撃しない。
- ボス弾は弾速5、飛距離20。予告範囲・攻撃発生は図形と色で確認できればよい。
- 10F以降も同じボスの行動を使い、数値で強くする。新しいボス素材や行動段階は初版の必須条件にしない。

### エンドレスで使える難易度の規則

フロア番号を `f` とし、以下を仮の調整式とする。0Fには適用しない。

- 通常フロアの敵数: `min(f + 2, 12)`。
- 射撃型の数: 1Fは0、それ以外は `floor(敵数 / 3)`。
- 重装型の数: 1〜2Fは0、それ以外は `floor(敵数 / 4)`。
- 残りを追跡型にする。例: 1Fは追跡3体、4Fは追跡3・射撃2・重装1体。
- ボスフロアはボス1体のみで、通常フロアの敵数式を使わない。
- 敵最大HP: `ceil(基礎HP × (1 + 0.12 × (f - 1)))`。
- 敵ダメージ: `max(1, floor(基礎ダメージ × (1 + 0.08 × (f - 1))))`。
- 同じHP・ダメージ倍率をボスにも適用する。敵数が上限に達しても数値の上昇は継続する。
- 移動速度と攻撃間隔はフロアによって変えない。
- 出現位置は種類ごとの固定順で割り当てる。ランダム配置は不要。

この式は動作確認用の出発点であり、面白さや適正難易度の保証ではない。係数を変えても進行・報酬ルールが変わらないようにする。

## 9. バックパック・装備・強化

### 所持品の分類

| 分類 | 置ける場所 | 効果・扱い |
| --- | --- | --- |
| 武器 | バックパック、武器A/B | 装備したスロットの入力で使用 |
| 救急キット・手榴弾 | バックパック、アイテムA/B | AはZ、BはXで使用して、その所持個体を消費 |
| シールド | バックパック、アイテムA/B | 装備中だけ自動防御・時間回復。個体ごとの残量を保持 |
| アップグレード | バックパック | 安全状態のUIから使用して消費。効果はそのラン中継続 |

- バックパックは3枠。装備枠4つは別枠で、最大7個を保持できる。
- 各アイテムは1枠を使い、スタックしない。装備・バックパック間で同じ個体を重複保持しない。
- バックパック内の装備には能力効果がない。
- 救急キット・手榴弾も1個で1枠を占める。使用後はその装備枠を空にし、バックパックから自動補充しない。
- 同種アイテムをA/B両方に装備できるが、別の所持個体が必要。
- 装備入れ替えは、選択したバックパックの品と装備中の品を交換する。バックパック満杯でも交換できる。
- 装備解除はバックパックの空きが必要。空きがなければ変更せず理由を表示する。
- バックパックの品は削除ボタンで破棄できる。地面には出さず、回収できない。装備中の品は一度解除してから破棄する。
- 型が合わない装備操作など、成立しない操作では元の状態を保つ。

### アイテムA/Bの3種類

| 種類 | 指定された効果 | 補足する初期案 |
| --- | --- | --- |
| 救急キット | HP全回復、使用すると失う | 発動時の最大HPまで即時回復。HP満タン時は発動せず消費しない。シールド残量は回復しない |
| 手榴弾 | 投げると爆発して大きなダメージ、使用すると失う | 使用時のエイム位置へ投げ、着弾時に範囲攻撃。基礎ダメージ100、爆発半径3、最大投擲距離8、飛行時間0.5秒を調整値とする |
| シールド | 装備中にHPの代わりにダメージを受け、HPと同容量で時間回復 | 容量はプレイヤーの最大HP。Z/X操作は不要で自動防御し、キーを押しても消費・切り替えはしない |

- アイテムA/Bに装備する種別は、救急キット・手榴弾・シールドの3種類とする。そのラン中に効果が続く能力強化は、後述するアップグレードで扱う。
- 救急キット・手榴弾は、ラン中かつ操作用UIが閉じていれば戦闘中・安全状態のどちらでも使用できる。バックパックから直接使用することはできない。
- Z/Xは押した瞬間だけ処理する。長押しによる連続使用はない。同時押しはA、Bの順に処理する。例えば救急キットを両方装備している場合、Aで全回復した後はBを消費しない。
- アイテム使用はその更新の入力処理で受け付け、以降に命中ダメージ・死亡を判定する。既に死亡・フロア移動中・リザルトの状態なら使用を受け付けない。
- 手榴弾は投擲が成立した時点で1個消費する。着弾や命中を待ってから消費する方式にはしない。
- 手榴弾の投擲先は床面のエイム位置を最大距離と部屋の内側に制限して決める。方向・位置が得られない入力では投げず、消費しない。
- 手榴弾は敵への途中接触では爆発せず、投擲先で爆発する。壁を越えて投げず、跳ね返りや物理的な転がりは不要。
- 爆発範囲内の各敵へ1回ずつ同じダメージを与える。距離減衰はなく、プレイヤー自身へのダメージもない。敵がいない場所に投げた場合も消費する。
- 手榴弾にも与ダメージ強化を適用し、投げた時点でダメージを確定する。弾道・爆発の見た目は図形でよい。

### シールドの容量・回復・複数装備（提案）

- 各シールドの最大容量は、その時点のプレイヤー最大HPと同じ値。現在HPが減っても容量は減らない。
- 新しく箱に生成された個体は容量満タン。取得・装備・解除・枠交換では残量を初期化しない。
- 被ダメージはアイテムAのシールド、アイテムBのシールド、プレイヤーHPの順に割り当てる。シールドがない枠は飛ばす。
- 例: HP100・シールド残量30で50ダメージを受けると、シールドは0、HPは80になる。
- シールドを2個装備した場合、それぞれ最大HPと同じ容量を持つ。最大HP100なら合計容量は200。これは複数装備を許可する初期案であり、ユーザー指定ではない。
- 残量0でもシールドは失われず、装備枠に残って回復を待つ。
- 正のダメージをプレイヤーが受けるたび、シールド回復の待ち時間をリセットする。全量をシールドで吸収した場合も含む。
- 被ダメージ後の待ち時間はプレイヤー共通で管理する。シールドを装備していない間もゲーム進行に伴って経過し、別のシールドへ交換してもリセットしない。
- 最後の被ダメージからゲーム進行時間で3秒後に、装備中の各シールドが毎秒最大容量の10%ずつ回復する。待ち時間と速度は調整値。同じ更新で被ダメージと回復が重なる場合は被ダメージを優先し、その更新では回復しない。
- 回復量の端数は時間に比例して累積し、整数1点ずつ残量へ反映して最大容量で止める。更新ごとの切り捨てで回復量を失わないようにする。
- 装備中であれば準備・クリア後も自然回復する。バックパック・箱内では回復しない。付け外しで被ダメージ後の待ち時間を消さない。
- フロア移動で残量と待ち時間を引き継ぐ。ポーズ・設定・所持品UI・フロア移動処理中は回復も待ち時間も進まない。
- 最大HPが増えた場合、シールド容量も増えるが現在の残量は増やさない。最大HPが減った場合は新容量まで残量を切り詰める。
- 救急キット、体力アップグレード、ボスクリアによるHP回復はシールド残量を直接回復しない。シールドは自然回復を続ける。

### ラン中のアップグレード（提案）

| 種類 | 効果の初期案 |
| --- | --- |
| 体力アップグレード | 使用でラン中の最大HP+10、現在HPも+10（最大HPまで） |
| 攻撃アップグレード | 使用でラン中の与ダメージ倍率に+0.05 |

- 最大HPは基礎値にラン中の体力強化を加算する。与ダメージ倍率は1に攻撃強化のボーナスを加算して求める。移動速度を変えるアイテムは初版に含めない。
- アップグレード使用時だけアイテムを1つ消費して効果を1回適用する。装備変更でその効果は失われない。
- アップグレードにラン中の回数上限は設けない。死亡後の再挑戦ではすべてリセットする。
- 武器個体のレベル上げ、合成、クラフト、売買、装備レアリティは初版に含めない。

## 10. 箱と選択ルール

- 箱は0Fと各ボスクリア時に1個だけ生成する。通常フロアには生成しない。
- 箱を開くと、箱の中身、バックパック、装備枠、比較可能な性能値を同じUIで確認できる。
- 取得は空きバックパックへ移す。満杯なら、バックパック内の1個と箱の1個を交換できる。交換で戻した品はその箱に残る。
- 初版では箱から装備枠への直接装備は行わず、バックパックを経由する。取得数の上限は設けない。
- UIを閉じて再度開いても内容と取得状況を保持する。開くたびの再抽選・補充はしない。
- 取り残した品は、そのフロアから移動すると消える。次のフロアへの持ち越しは所持品だけ。

### 容量だけでは選択が起きない点

バックパック3枠に対して箱に4個入れるだけでは、装備枠へ移して全品を持てることがある。
消費して枠を空けられる救急キット・手榴弾・アップグレードだけで品数を増やしても、非消費装備の選択が必要になるとは限らない。
そのため、3種類のアイテムを含む箱の初期案を以下とする。

| 内容 | 個数 |
| --- | --- |
| 武器候補 | 6個。武器3種類について、それぞれ威力と使用間隔が異なる固定候補を2個ずつ |
| 救急キット | 1個 |
| 手榴弾 | 1個 |
| シールド | 1個 |
| 体力・攻撃アップグレード | 各1個 |
| 合計 | 11個 |

武器を保持できる場所は武器A/Bとバックパックの計5枠なので、箱の武器6個をすべて保持することはできない。
また、バックパックに予備の消費品・シールドを残すと、予備武器に使える枠が減る。
別素材やレアリティ抽選を増やさず、どの武器とアイテムを次のフロアへ持っていくかを選べる構成にする。
ラン中の強化2個を両方使えることは許容する。

- 初期箱とボス報酬箱はそれぞれ固定の内容表を持つ。
- ボス箱は同じ内容表を繰り返し使う。継続的な成長は少なくともアップグレード2個で成立する。
- 上記の個数・配分・個別性能は調整値。ただし「装備候補をすべて保持できない」という要件は維持する。
- 箱を無視しても初期武器で進める。報酬の取得をポータル解放条件にはしない。

## 11. フロア間・ラン間の持ち越し

| 状態 | 次のフロア | 死亡後の新規ラン |
| --- | --- | --- |
| 現在HP | 維持。ボスクリア時のみ全快が入る | 初期最大HPで全快 |
| 装備・バックパック | 維持 | 初期武器以外なし |
| シールドの個体別残量と共通の回復待ち時間 | 維持。移動処理中は時間を進めない | 個体と待ち時間を消去 |
| アップグレード効果 | 維持 | すべて消去 |
| 攻撃クールダウン | リセットして使用可能にする | リセット |
| プレイヤー位置・向き | 所定の入場位置・向きへ | 0Fの開始位置・向きへ |
| 敵・弾・手榴弾・爆発・攻撃判定 | 前フロアのものを消す | すべて消す |
| 箱の未取得品 | 前フロアのものを消す | すべて消す |
| フロア番号・経過時間・各カウント | 継続・加算 | 初期化 |
| 適用済みの設定 | 維持 | 維持。アプリを再起動しても読み戻す |

途中セーブ、コンティニュー、永久成長、前回装備の持ち越し、ベスト記録の永続保存は初版に含めない。
音量・画面モードの設定保存は、ランのセーブとは別に行う。

## 12. オープニングメニュー・設定・HUD・リザルト

オープニングメニューと設定画面を初版に含めることはユーザー指定。以下の項目・遷移・保存方法は初期案である。

### オープニングメニュー

- アプリ起動時に表示し、まだフロアやラン時間を進めない。タイトル文字と単純な背景・ボタンでよい。オープニング映像は不要。
- 「ゲーム開始」: 新規ランを初期化し、0Fへ進む。繰り返しクリックしてもランを重複生成しない。
- 「設定」: 設定画面へ進み、閉じるとオープニングへ戻る。
- 「終了」: スタンドアロンのアプリを終了する。Unity Editorそのものは終了させない。
- 操作一覧としてWASD、マウス、左右クリック、Z/X、E、Tab、Escを表示する。
- 途中セーブはないため「つづきから」は設けない。再挑戦はオープニングを経由せず0Fから始められる。

### ポーズメニューと戻り先

- ラン中のEscで「再開」「設定」「メニューへ（現在のランを終了）」を表示する。
- 設定を閉じたときはポーズメニューへ戻り、勝手に戦闘を再開しない。
- メニューへ戻る場合は現在のラン、敵、弾、手榴弾、箱、所持品を片付ける。中断を死亡として数えたり、死亡リザルトを作ったりしない。
- リザルトからも「再挑戦」「メニューへ」を選べる。
- メニュー、設定、リザルトの入力で背後のゲームが進行したり、消費アイテムが使われたりしない。

### 設定画面

初版では次の2項目を用意する。ゲーム難易度や装備性能の調整はユーザー向け設定に含めない。

| 項目 | 初期案 |
| --- | --- |
| 全体音量 | 0〜100%、初期値100%。0%でミュート。再生されるゲーム音・UI音の両方に適用 |
| 画面モード | ウィンドウ / ボーダーレス全画面。初期値はウィンドウ |

- 設定を開くと適用済みの値を編集用にコピーする。編集中はまだ適用・保存しない。
- 「適用して戻る」で値を適用・保存し、開いた元のメニューへ戻る。
- 「キャンセル」またはEscで未適用の変更を捨て、元のメニューへ戻る。
- 「初期値に戻す」は編集用の値だけを初期値に戻す。適用するまでは保存済み設定を変えない。
- 適用済み設定は端末ローカルに保存し、アプリ起動時に読む。未保存・不正な値は初期値で扱う。
- オーディオ素材がない段階でも音量値の設定・保存は可能とし、音源を追加した際にその値を共通で反映する。音量確認用に本格的な音源制作を要求しない。
- 画面モードはスタンドアロンで反映を確認する。Unity Editorでの設定操作はEditorウィンドウの表示状態を変更しない。
- 解像度一覧、画質プリセット、キー変更、言語切り替えは初版の必須条件にしない。マウスの床面位置へ直接向く操作のため、エイム感度の項目は設けない。

### 常時HUD

- 現在フロア、ボスフロアの表示、残り敵数。
- プレイヤーの現在HP / 最大HP。
- 武器A/Bの名称と使用可能状態、アイテムA/Bの名称とZ/Xの割り当て、バックパック使用枠数。
- 救急キット・手榴弾は使用後に空枠表示へ更新。シールドは「自動」と個体別の現在残量 / 最大容量、回復待ち・回復中の状態を表示する。HPゲージとは分ける。
- 現在の目標。「箱で準備」「敵を全滅させる」「ポータルで次へ」など。
- 近くの箱の操作案内、ポータルの移動先。
- 敵のHPと攻撃予告。小さなゲージや数値、範囲図形でよい。

### 箱・所持品UI

- 名前、種別、効果、武器のダメージ・使用間隔、シールド個体の現在残量 / 最大容量を表示する。
- 取得、交換、装備、解除、アップグレード使用、破棄、閉じるを操作できる。
- 容量不足や型違いで操作できない理由を表示する。
- 現在の最大HP、攻撃倍率、移動速度を表示し、変更結果を確認できる。

### リザルト

- ゲームオーバーと死亡したフロア。
- 到達フロア（入場した最大の戦闘フロア）とクリアフロア数（0Fを除く）。
- ボスを含む敵撃破数、ボス撃破数。
- ランの経過時間。新規ラン開始から死亡までのゲーム進行時間とし、UI・ポーズ・フロア移動処理中は除外する。
- 死亡時の装備とアップグレード合計。
- 再挑戦ボタン、メニューへ戻るボタンと操作案内。

終了後は結果を固定し、残った攻撃やUI操作でカウント・装備が書き変わらないようにする。

## 13. 必要なプレースホルダと初版の範囲

- プレイヤー1種。円柱・カプセル等に向きを示す三角形を付ける。
- 雑魚3種とボス1種。色・大きさ・形状で区別する。
- 床と外周壁からなるアリーナ1種。全フロアで再利用する。
- 箱1種、ポータル1種。立方体と円・リングでよい。
- 弾、近接範囲、ボス予告、手榴弾と爆発範囲、シールドの図形表示。
- オープニングメニュー、設定画面、HUD、箱・所持品UI、ポーズ、リザルト。
- 武器3種、救急キット・手榴弾・シールド、アップグレード2種の定義と固定候補表。

本格的なアニメーション、音声、VFX、カメラ演出、武器専用モデル、複数バイオーム、ストーリー、クエスト、ショップ、通貨、ネットワーク協力、ゲームパッド対応は初版の必須条件にしない。
種類を増やすより、既存の種類で進行・選択・強化・終了の一巡を完成させる。

## 14. 完成と判断できる受け入れ条件

以下は初版の受け入れ条件。Unityの自動テスト、実シーンの描画確認、スタンドアロン操作を組み合わせて確認した。各条件の証拠と確認範囲は[検証表](unity-only-arena-verification.md)を参照する。音源のない初版では、実音のミュート確認は条件付きの対象外とする。

- [x] Unityだけで起動でき、オープニングからゲーム開始を選ぶと、バックエンドなしで0Fの箱とポータルが利用できる。
- [x] オープニングとポーズから設定を開け、適用・キャンセル後は元のメニューへ戻る。設定からポーズへ戻っても戦闘は再開しない。
- [x] 音量・画面モードの適用、未適用変更のキャンセル、初期値への復帰、アプリ再起動後の読み戻しができる。音源がある場合は音量0でミュートされる。
- [x] スタンドアロンで画面モード切り替えとアプリ終了ができる。EditorではEditor自身を終了させない。
- [x] ポーズ・リザルトからメニューへ戻り、改めて開始すると前のランの状態が残らない。設定は維持される。
- [x] マウスに向き、WASDで移動しながら、A/Bの両武器を使用できる。
- [x] 雑魚3種とボス1種が、それぞれ定義した攻撃でHPを減らす。
- [x] 予定した全敵を倒す前にはポータルが出ず、全滅後に1個だけ出る。
- [x] 1〜4Fの攻略、5Fのボス、報酬選択・強化、6Fの攻略が一続きで動作する。
- [x] 10Fのボス後も11Fへ進める。勝利による強制終了やフロア定義切れがない。
- [x] 後のフロアで敵数またはHP・ダメージが増え、規定数を超える敵は出ない。
- [x] 敵は装備・消費品・アップグレードをドロップしない。
- [x] 箱の装備候補をすべて保持することはできず、満杯時でも交換して選び直せる。
- [x] 箱の開閉で報酬が復活せず、入れ替え・装備・解除で品が重複したり消失したりしない。
- [x] アップグレードは1個消費して1回だけ効果が出る。
- [x] ZでアイテムA、XでアイテムBを使用し、救急キットはHP全回復、手榴弾は範囲内の各敵への大ダメージになる。使用後はその個体だけが消え、枠が空になる。
- [x] 救急キットはHP満タン時に消費されず、手榴弾は敵に当たらなくても投擲時に消費される。長押し・UI操作・メニュー復帰で意図しない追加使用が起きない。
- [x] シールド容量は最大HPに追従し、HPより先にダメージを吸収する。超過分だけがHPに入り、0になってもアイテムを失わない。
- [x] シールドを2個装備した場合はA、B、HPの順で吸収する。シールド枠のZ/X入力は防御の切り替えや消費を起こさない。
- [x] シールドは被弾後の待ち時間が過ぎてから規定速度で回復する。バックパック・箱・UI・ポーズ・設定・フロア移動処理中は回復しない。
- [x] シールドの付け外し・箱との交換・フロア移動で残量が初期化されない。最大HP増加や救急キットでシールド残量が即座に増えない。
- [x] 通常フロアのHP持ち越し、ボス後の1回だけの全回復、装備・強化の持ち越しが働く。
- [x] 空の武器スロット、両武器未装備、ポータルとの重なり、UIクリックで意図しない攻撃・進行が起きない。
- [x] プレイヤーと最後の敵の同時死亡は敗北になる。クリア後の残存弾で死亡しない。
- [x] HP0でリザルトが固定され、再挑戦ですべてのラン状態が初期化される。
- [x] 操作用UI表示・ポーズ・設定中は戦闘、アイテム使用、シールド回復、計時が停止し、元の状態から再開できる。

## 15. 実装に進む際の方針案

実装に進む場合は、[Unity-onlyデモのプロジェクト](../../kitu-integration-runner/unity-demo-game/README.md)で、以下の順に小さく分ける。

1. オープニング・設定・ラン開始。
2. 移動・マウスエイム・2武器・HP。
3. 通常フロアと死亡・再挑戦・メニュー復帰。
4. 箱と装備・強化・3種類のアイテム。
5. 雑魚3種とボス周期・難易度上昇。
6. 0Fからボス後の次フロアまでの一巡と、第14章の境界条件の検証。

初版は既存Unityプロジェクト内の `Assets/KituDemoApp/EndlessArena/EndlessArena.unity` で起動する。元の `KituDemoAppMain.unity` は比較用のスモークテストとして保持する。
`ArenaGame` が入力・画面遷移、`ArenaSimulation` が戦闘・フロア進行、`ArenaInventory` が所持品・HP・シールド、`ArenaHud` と `ArenaWorldView` が表示を担当する。すべてUnityプロジェクト内のC#で動作する。今回の指定である「敵アイテムドロップなし」「死亡までエンドレス」「Z/Xの装備アイテム」は新しいアリーナの経路に適用する。

Unity-onlyを比較基準として維持し、実装で生じた困りごとを記録してから必要な部分をKituへ移す。
フロア進行、HP・戦闘、所持品、強化、報酬の状態と、入力・見た目・UIの担当箇所を把握できるようにする。
ただし、最初からKitu向けの通信層、汎用ゲーム基盤、決定論的リプレイ、セーブ基盤を完成条件として追加しない。
実装で観測していない困りごとを実績として記録しない。
